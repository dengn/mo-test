范围与可复现性

  • 100 scenario definitions ×1000 parameter tuples, not 100000 unrelated SQL grammars.
  • SQL-only oracle is DuckDB 1.3.2; six definitions cross-checked with NumPy/Pandas in 168 checks.
  • Client numerical/ML algorithms run in NumPy; MO provides SQL-derived features. Shared numerical implementation checks data interoperability, not independent algorithm correctness.
  • Explicit DOUBLE casts used for scientific arithmetic. Initial pilot decimal-scale differences are retained separately and not treated as engine wrong-result defects.
  • Main workload is read-only on 113830 deterministic rows across nine tables, 24 customers without facts, missing credits and skewed customers.
  • Local single-instance warm workload and simultaneous local oracle/client CPU use; no distributed HA, crash/restart, production-load or multi-node guarantee.
  • Query timings are client-visible observations under mixed load, not isolated MO engine benchmarks.
