## 稳定性与结果

- 记录的当前日志与 5 份重启前日志中，panic、fatal error、SIGSEGV、runtime error 共 0 条；监控期 OOM / OOM kill 为 0。这是本次覆盖范围内的观察结果。
- 5 次主动 SIGKILL，压力并发 16/32/64/96/128；1,597 条已确认写入记录均在恢复后存在且数值正确。未收到确认的事务单独记录，不记为丢失。
- 混沌 50,000 条完成；40 条校准残留重复键在移除校准数据后重放通过；1 条向量排序差异按 float32 精度复核通过。原始失败记录保留。
- 跨库场景 100,000 条完成；原始 2 条排序差异用独立 float32 输入与累加重新计算预期，均通过。未部署其他六种数据库，验证的是文档场景的 MatrixOne 实现。
- ETL 100,000 条全部通过，包括 1,000 次真实 CSV 导入及 1,000 次服务端 CSV/JSONLINE/Parquet 导出，使用独立格式解析核对。Snowflake/Fivetran/dbt 场景以 SQL 和模拟连接器消息实现，未验证实际 SaaS 或 dbt adapter。
- 20 万补漏实例执行完毕：约束、复杂连接/CTE、窗口/集合运算、混合类型、高维向量、全文语法边界、取消查询、断连回滚、原子更新。3,000 组并发原子更新、3,000 组断连、3,000 组取消均完成。

## 缺陷和差异的区分

**确认 1 组持久的索引元数据异常**：额外并发索引测试（25 个 DDL 操作，8 个写线程、24 个读线程及最多 8 个 DDL 线程）中，HNSW 表并发创建/删除普通二级索引及重建后，出现内部二级索引表不存在。负载停止后新连接 INSERT、REINDEX 仍报 1146，SHOW CREATE TABLE 报缺失索引可见性元数据。已确认写入的 153 行核对缺失 0、错误 0。二级索引创建/删除组合曾报内部 delete_rowid 重复键，暂归同一竞态症状，独立根因数待确定。3 组串行对照均正常；尚未定位代码根因。

证据：index-race.py、index-race.json、index-race-ledger.json、index-fresh-session-recheck.json、review.py。受影响表保留在测试库，未修复或删除。

另外有 5 类可复现兼容性候选，不能直接按实例数认定 bug：数字日期、数字时间、相邻字符串字面量拼接、超大 unsigned ROUND/TRUNCATE 精度参数、零日 LAST_DAY。示例及两引擎输出见 minimal-reproductions.json 与 problem-groups.json。BOOL 算术、MAKETIME 截断范围、默认二进制排序、LOCATE 大小写行为在文档中与 MySQL 不同，单列为行为差异。没有 ORDER BY 的 UNION 排序差异按多重集合复核；12 条 TRUNCATE 并发锁冲突串行重放均通过。

全文第二代索引在增量写入后的可见性仍需专门复核；并发测试结束时源表 558 行、全文可见 520 行，暂记录为异步索引/缓存新鲜度现象，没有证据认定持久数据丢失。

## 运行条件与限制

MatrixOne main 固定提交 `2726fb419b3afa1db2686ae1b2aaca563d1ae214`，MySQL 对照 `8.0.46`，4 CPU / 32 GiB，单进程 LOG/TN/CN，本地生成数据。多数精确断言使用 200/2,000 行固定数据，另有此前大数据量压力测试；大用例数量不能证明 TB 级规模或分布式故障行为。边界语法仅要求干净拒绝或返回，不等同于所有语法语义均正确。资源监控未覆盖最早三批的全程。

原始记录 results.jsonl、复核 resolved-results.jsonl 同时保留；summary.json 提供逐包分类，problem-groups.json 提供分组样例。重放入口见 README.md。

本报告仅对应已经结束的 500,000 条；随后追加的两批各 50,000 条独立保存，不混入此处完成计数。
